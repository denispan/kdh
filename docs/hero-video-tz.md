# ТЗ на hero-видео главной страницы

Объект: фоновое видео в секции [HeroVideo.astro](src/sections/HeroVideo.astro) —
`/video/hero.webm` + `/video/hero.mp4`, постер `/video/hero-poster.jpg`.

Режим воспроизведения на сайте: `autoplay muted loop playsinline`, `object-cover object-top`,
высота секции `min-h-svh` (вся высота вьюпорта). Видео **растягивается по ширине окна и
кадрируется** — это определяет требования к разрешению и композиции.

---

## 1. Разрешение

### Какой монитор считаем целевым

По статистике десктопа (StatCounter, 2025–2026) самое распространённое разрешение —
**1920×1080 (Full HD)**, ~20–25 % всех устройств и порядка половины десктопов.
Второй по массовости класс — ноутбуки 1536×864 / 1366×768 (это Full HD-панели при
масштабе 125–150 %, т.е. CSS-ширина меньше, а физических пикселей всё равно до 1920).
Отдельно: Retina/2×-ноутбуки (MacBook, 2880×1800 и выше) и мониторы 2560×1440.

### Требование: три варианта по разрешению

Цель — отсутствие пикселизации на любом экране, включая 4K-мониторы и Retina-ноутбуки.
Поэтому сдаются **три версии одного и того же кадра**, сайт выбирает нужную по
ширине вьюпорта × DPR (см. §4).

| Вариант | Разрешение | Когда отдаётся браузеру |
|---|---|---|
| `hero-2160` (4K) | **3840×2160** | эффективная ширина > 2560 px: 4K-мониторы, Retina-ноутбуки (2× при окне ≥1440 CSS-px) |
| `hero-1440` (2K) | **2560×1440** | эффективная ширина 1921–2560 px: мониторы 2560×1440, окна 1440p |
| `hero-1080` (Full HD) | **1920×1080** | эффективная ширина ≤1920 px: самый распространённый монитор + мобильные |

Мастер-исходник, из которого делаются все три: **не ниже 3840×2160, 16:9** (лучше —
съёмка/рендер в 4K или выше, чтобы 4K-версия была нативной, а не апскейлом).

Почему так:
- **1920×1080 — абсолютный минимум.** Видео растянуто на 100 % ширины окна
  (`object-cover`), значит при окне 1920 px нужен кадр ровно 1920 px по горизонтали;
  апскейл 1280→1920 даёт мыло и «лестницу» на контрастных краях.
- **2560×1440** закрывает распространённый класс 1440p-мониторов, где 1080p уже
  заметно мылит на резких границах.
- **3840×2160** нужен для 4K-мониторов и для 2×-экранов: на MacBook с окном
  1512 CSS-px браузер рисует ~3024 физических пикселей, и 1080p там видно как
  размытие. 4K-версия снимает вопрос пикселизации полностью.
- Отдавать 4K всем **нельзя**: файл в 3–4 раза тяжелее и утопит LCP на Full HD и
  мобильных. Отсюда — переключение вариантов, а не один тяжёлый файл.

### Кадрирование и композиция (важно, т.к. `object-cover`)

- Соотношение сторон мастера — **16:9**.
- На широких мониторах (21:9) и особенно на **мобильных (9:16–3:4)** кадр обрезается
  по бокам. Всё смысловое — **в центральных 60 % по ширине** (safe zone
  ≈ 1150 px из 1920).
- Выравнивание `object-top`: обрезка идёт **снизу**. Ключевой объект — в верхней
  и центральной части кадра, нижние ~25 % высоты считать расходной зоной.
- Верхние ~130 px перекрывает шапка сайта, низ затемнён градиентом
  (`from-black via-black/40`) — не размещать там мелких деталей и титров.
- Титры/текст в самом видео — не использовать (не масштабируются, не переводятся).

## 2. Кодеки и параметры кодирования

Каждое из трёх разрешений кодируется в **два формата**: WebM/VP9 (основной) и
MP4/H.264 (фолбэк). Итого 6 видеофайлов. Внутри одного разрешения браузер берёт
первый поддерживаемый `<source>` (порядок: webm → mp4).

### 2.1. WebM / VP9 — основной

| Параметр | Значение |
|---|---|
| Контейнер | `.webm` |
| Видеокодек | **VP9** (`libvpx-vp9`), profile 0, 8 бит |
| Цвет | `yuv420p`, BT.709 |
| Битрейт (CQ-режим `-b:v 0`) | 1080p: `-crf 32`, ~2.5–3.5 Mbps · 1440p: `-crf 31`, ~5–7 Mbps · 2160p: `-crf 30`, ~10–14 Mbps |
| Аудио | **отсутствует полностью** (видео `muted`) |

Зачем: VP9 при том же качестве весит на 25–35 % меньше H.264. Поддержка — Chrome,
Firefox, Edge, Safari 14+ (~96 % трафика).

### 2.2. MP4 / H.264 — фолбэк

| Параметр | Значение |
|---|---|
| Контейнер | `.mp4`, **`-movflags +faststart`** (moov-атом в начале — иначе не стартует до полной загрузки) |
| Видеокодек | **H.264 (AVC), High profile, level 4.0** |
| Цвет | `yuv420p` (не 4:2:2/4:4:4 — не играет в браузерах), BT.709 |
| Битрейт | 1080p: `-crf 23`, 4–6 Mbps · 1440p: `-crf 23`, 8–11 Mbps · 2160p: `-crf 22`, 16–22 Mbps |
| Уровень | 4.0 для 1080p, **5.1 для 1440p и 2160p** |
| Аудио | отсутствует |

Зачем: 100 % совместимость, включая старые iOS/Safari и корпоративные Windows.

### 2.3. Общее для обоих

- **Частота кадров: 25 или 30 fps**, постоянная (CFR). Не 50/60 — фон, выигрыша нет,
  вес +40 %. Не VFR — ломает бесшовный цикл.
- **Прогрессивная развёртка** (`p`, не interlaced), без телесина.
- **Keyframe interval (GOP): 2 с** (`-g 50` при 25 fps), closed GOP — для быстрого
  старта и корректного `loop`.
- **Длительность: 8–15 с.** Бесшовный цикл: первый и последний кадр совпадают по
  композиции, экспозиции и движению; без вспышек, склеек и затемнений на стыке.
- **Целевой вес готового файла: до 5 МБ (webm) и до 8 МБ (mp4)** для 1080p.
  Сейчас в репозитории 21.6 МБ webm и 12.7 МБ mp4 — это в 3–4 раза выше нормы для
  автоплей-фона и напрямую бьёт по LCP.
- Метаданные, главы, тайм-код, альфа-канал — не нужны.
- Не должно быть: резких вспышек/стробоскопа (доступность), важной анимации в первые
  0.5 с (не успевает прогрузиться), сильного зерна/шума (убивает битрейт).

### 2.4. AV1 — не требуется

Даёт ещё −30 % веса, но кодируется долго и не покрыт частью Safari/старых Android.
Можно добавить третьим `<source>` первым по порядку позже, отдельной задачей.

## 3. Постер (`hero-poster.jpg`)

- Кадр из видео — **первый кадр**, точно совпадающий с началом воспроизведения
  (иначе будет «дёрганье» при старте).
- Разрешение: **1920×1080**.
- Формат: JPEG q≈80 (до 200 КБ) обязательно; WebP/AVIF — опционально дополнительно.
- Цветовой профиль: sRGB, встроенный.

---

## 4. Что сдаётся

1. `hero_master.mov|mp4` — 3840×2160, ProRes 422 или H.264 CRF 16 (мастер, для перекодировок).
2. `hero.webm` — 1920×1080, VP9, без звука, ≤5 МБ.
3. `hero.mp4` — 1920×1080, H.264 High, faststart, без звука, ≤8 МБ.
4. `hero-poster.jpg` — 1920×1080, sRGB, ≤200 КБ, = первый кадр.

Приёмка: цикл незаметен на 3 повторах подряд; нет пикселизации и полос (banding) на
градиентах при просмотре в полный экран на 1920×1080; старт воспроизведения без
чёрной вспышки и без рывка от постера; сумма веса hero-ассетов не превышает ~8 МБ.

## 5. Референсные команды ffmpeg (из мастера 4K)

```bash
ffmpeg -i hero_master.mov -an -vf "scale=1920:1080:flags=lanczos,format=yuv420p" -r 25 \
  -c:v libvpx-vp9 -crf 32 -b:v 0 -g 50 -row-mt 1 -tile-columns 2 -deadline good -cpu-used 1 \
  hero.webm
```

```bash
ffmpeg -i hero_master.mov -an -vf "scale=1920:1080:flags=lanczos,format=yuv420p" -r 25 \
  -c:v libx264 -profile:v high -level 4.0 -crf 23 -maxrate 6M -bufsize 12M \
  -g 50 -keyint_min 50 -sc_threshold 0 -preset slow -movflags +faststart \
  hero.mp4
```

```bash
ffmpeg -i hero_master.mov -vf "scale=1920:1080:flags=lanczos" -frames:v 1 -q:v 3 hero-poster.jpg
```
